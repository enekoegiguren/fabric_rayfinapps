# Metrics strategy: `.docs/METRICS.md`

Each app keeps one document that answers, for every page: **which numbers it shows, with which DAX, filtered by which
model column, and coloured by which threshold.** It's the document the business owner reviews and the one the agent
reads before changing a page.

## The rule: generated, never written

`METRICS.md` is **generated from the app's own constants** by `npm run docs:metrics`. Nobody edits it by hand.

Hand-written metric docs drift the week after they're written. Generated from code, the doc can't say something the
app doesn't do: change the code, regenerate, and the diff of `METRICS.md` in the PR shows the business exactly which
number changed.

## What the app needs for it

Keep the definitions as data, not scattered through components:

| Constant | Holds |
|---|---|
| KPI catalog (`src/services/kpiCatalog.ts`) | Key, label, description, DAX, thresholds (amber / red), where the user acts on it |
| Page cards (`*_METRICS` exported from the page components) | The cards of each page: key, label, DAX for the period and the previous year |
| Filter sets (exported from the filter panel) | The filters of each page and the model column behind each one |
| Query builders (`src/services/<app>Queries.ts`) | All DAX, as named functions. User values only through an escaping helper |

The generator (`scripts/metrics-doc.ts`, run with `vite-node`) imports those constants and writes markdown tables.

```jsonc
// package.json
"scripts": {
  "docs:metrics": "vite-node scripts/metrics-doc.ts"
}
```

```typescript
// scripts/metrics-doc.ts (skeleton)
import { writeFileSync } from 'node:fs';
import { KPIS } from '../src/services/kpiCatalog';
import { SALES_METRICS } from '../src/components/Dashboard';
import { SALES_FILTERS, FILTER_COLUMN } from '../src/components/FilterPanel';

const lines: string[] = ['# <App> — metrics and filters', '', 'Generated by `npm run docs:metrics`. Do not edit.', ''];

lines.push('## KPIs', '', '| KPI | DAX | Amber | Red |', '|---|---|---|---|');
for (const k of KPIS) lines.push(`| **${k.label}** (\`${k.key}\`) | \`${k.dax}\` | ${k.amber} | ${k.red} |`);

lines.push('', '## Sales', '', '| Card | Key | DAX |', '|---|---|---|');
for (const m of SALES_METRICS) lines.push(`| ${m.label} | \`${m.key}\` | \`${m.dax}\` |`);
lines.push('', `- **Filters**: ${SALES_FILTERS.map((f) => f.label).join(' · ')}`);

lines.push('', '## Filters: model column', '', '| Filter | Column |', '|---|---|');
for (const [key, col] of Object.entries(FILTER_COLUMN)) lines.push(`| \`${key}\` | \`${col}\` |`);

writeFileSync(new URL('../.docs/METRICS.md', import.meta.url), lines.join('\n') + '\n');
```

## The guard: only measures the model has

Add a test that reads the model definition committed in Git (TMDL) and fails when the app's DAX references a measure
the model doesn't have. The app can't invent a measure; it has to be added to the model first, where every report,
Copilot and data agent gets it too.

## Sections of a METRICS.md
1. **KPIs**: grouped by area. Value (DAX), the numbers behind it, default severity, rule, where it's worked on.
2. **Pages**: one sub-section per page and tab, its route, its cards (key + DAX), its filter bar.
3. **Filters: model column**: every filter key and the `Table[Column]` it filters.

## Checklist
- [ ] Changed a KPI, card or filter → `npm run docs:metrics` → commit `METRICS.md` in the same PR
- [ ] The measures-in-model test passes
- [ ] The business owner has read the `METRICS.md` diff
